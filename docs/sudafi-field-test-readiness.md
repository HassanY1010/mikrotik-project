## 2. تدقيق تكامل مصمم صفحات HotSpot (المسار الكامل)

تم فحص ومراجعة المسار الكامل لتصميم ونشر صفحات الدخول:
$$\text{Flutter / Web Admin} \longrightarrow \text{Backend API} \longrightarrow \text{Command Queue} \longrightarrow \text{Windows LAN Agent} \longrightarrow \text{RouterOS}$$

### 2.1 حفظ القوالب، المعاينة، والاسترجاع
- **الأدلة في الكود:** 
  - `apps/api/src/modules/portal/portal.service.ts` (الأسطر 145-230): توفر التوابع `listTemplates`، `getTemplate`، `createTemplate`، `updateTemplate`، و `deleteTemplate`.
  - `apps/api/src/modules/portal/portal-compiler.service.ts` (الأسطر 40-150): يقوم بتوليد كود HTML5 متجاوب حديث.
- **آلية المعاينة:**
  - يتم استدعاء `POST /portal/preview-draft` للمعاينة اللحظية للمسودة أو `GET /portal/templates/:id/preview` للقوالب المحفوظة.
  - في وضع المعاينة (`preview`)، يتم استبدال متغيرات ميكروتك ببيانات تجريبية ومحاكاة نموذج تسجيل الدخول دون إرسال أي أوامر للراوتر.

### 2.2 عزل القوالب بين أصحاب الشبكات (Tenant Isolation)
- **الأدلة في الكود:**
  - `portal.service.ts` (الأسطر 85-142): تخزين القوالب معزول تماماً ومفهرس بواسطة `tenantId`.
  - كل طلب API يخضع للتحقق من التوكن واستخراج `req.user.tenantId` عبر حارس الـ JWT وحارس الـ RBAC.
  - لا يمكن للمستأجر (A) رؤية أو تعديل قوالب المستأجر (B).

### 2.3 التحقق من صلاحيات نشر الصفحة (Device Ownership Check)
- **الأدلة في الكود:**
  - `portal.service.ts` (الأسطر 329-334):
    ```typescript
    const device = await this.devicesService.findById(tenantId, deviceId);
    if (!device) {
      throw new NotFoundException(`Device with ID ${deviceId} not found for this tenant`);
    }
    ```
  - يتم رفض محاولة النشر فورياً بـ `404 Not Found` أو `403 Forbidden` إذا كان معرف الجهاز لا ينتمي للمستأجر الحالي.

### 2.4 رفع الملفات وسلامة المسارات (Directory Traversal & Security)
- **الأدلة في الكود:**
  - تعقيم أسماء المجلدات والملفات في `portal.service.ts` (السطر 351):
    ```typescript
    if (!/^[a-zA-Z0-9_-]+$/.test(directoryName)) {
      throw new BadRequestException('Target directory name must be alphanumeric with no slashes or spaces');
    }
    ```
  - حماية الوكيل في `apps/agent/src/router/routeros-worker.ts` (الأسطر 760-775):
    - فحص صارم لاسم المجلد واسم كل ملف ضد التعبيرات النمطية `^[a-zA-Z0-9_.-]+$`.
    - منع كامل لأي محاولة استخدام `../` أو أقواس أو مسارات جذرية غير مصرح بها.
- **الحماية ضد هجمات XSS:**
  - يقوم `PortalCompilerService` بتطهير كافة النصوص المدخلة (اسم الشبكة، نصوص الشروط، نصوص التذييل) وإزالة وسوم `<script>` أو الروابط الملغومة بواسطة تعقيم النصوص الصارم.

### 2.5 التعامل مع الصور والروابط الخارجية
- الشعار يُقبل كـ `logoUrl` (رابط HTTPS خارجي). 
- **ملاحظة للميدان:** إذا كانت شبكة الهوتسبوت تعمل في وضع "Walled Garden" مغلق تماماً قبل تسجيل الدخول، فإن الراوتر قد يحجب تحميل الصورة الخارجية ما لم يتم إضافة نطاق الصورة إلى `/ip/hotspot/walled-garden/ip`.
- **التوصية:** يفضل في التحديثات اللاحقة دعم تحويل الشعار الصغير إلى Data URI Base64 مدمج داخل كود HTML لتفادي مشاكل الـ Walled Garden.

### 2.6 توافق التنفيذ الفعلي مع RouterOS v6 و RouterOS v7
- **آلية الرفع الحالية:** الوكيل يستخدم أوامر ميكروتك API:
  - `/file/print ?name=hotspot/login.html` للتحقق من الوجود.
  - `/file/add =name=hotspot/login.html =contents=...` للإنشاء.
  - `/file/set =.id=... =contents=...` للتعديل.
  - `/ip/hotspot/profile/set =.id=... =html-directory=hotspot` لربط البروفايل بالمجلد.
- **ما لا يمكن التأكد منه إلا براوتر حقيقي (Router Real-Hardware Gaps):**
  1. **حد طول السلسلة النصية في RouterOS API:** في بعض إصدارات RouterOS v6/v7، أمر `/file/add =contents=` قد يفشل إذا تجاوز حجم ملف الـ HTML حاجز الـ 4096 حرفاً، ويتطلب الرفع عبر FTP أو SFTP المدمج في الراوتر، أو التجزئة. (ملفات SudaFi الحالية مضغوطة ومنمنمة بحجم ~2.5KB مما يجعلها ضمن الحدود الآمنة، ولكن يلزم فحص ذلك عملياً).
  2. **بنية الأقراص في أجهزة Flash (RouterOS v7):** الأجهزة التي تعتمد على ذاكرة وميضية داخلية مثل hEX أو hAP ac تضع مجلد الهوتسبوت تحت `flash/hotspot` وليس `hotspot` مباشرة في الجذر. الوكيل يتيح تخصيص `directoryName`، ولكن يجب التحقق من مسار التخزين الافتراضي بحسب طراز الجهاز المختبر.

## 3. مراجعة متطلبات العميل المتبقية والنموذج التجاري

### 3.1 آلية تسجيل أصحاب الشبكات وتفعيل حساباتهم
- **الوضع البرمجي الفعلي:**
  - الباك إند يحتوي بالفعل على نقطة نهاية `POST /auth/register` تقوم بإنشاء منظمة المستأجر (`Tenant`)، حساب المدير الإداري (`TENANT_ADMIN`) بكلمة مرور مشفرة بـ Argon2id، واشتراك تجريبي مجاني مدته 30 يوماً (`Free Trial`).
  - واجهات المستخدم الحالية (Web Admin و Flutter) لا تحتوي على زر أو شاشة تسجيل ذاتي (Self-Service Registration)، والدخول متاح فقط بتسجيل الدخول للحسابات المنشأة.
- **خيارات القرار المطلوب من صاحب المشروع:**
  1. **الخيار (أ) - التسجيل الذاتي المباشر (Self-Serve Signup):** إضافة شاشة تسجيل في تطبيق الهاتف ولوحة الويب تمنح العميل حساباً تجريبياً فورياً لمدة 14 أو 30 يوماً. *(المخاطر: احتمال إساءة استخدام الخدمة بإنشاء حسابات وهمية متكررة).*
  2. **الخيار (ب) - التسجيل مع الموافقة الإدارية (Pending Approval):** يسجل العميل بيانات شبكته، وتظهر لـ Super Admin كطلب انضمام معلق يتم تفعيله يدوياً. *(الأكثر أماناً للاختبار الميداني الأول).*
  3. **الخيار (ج) - الإنشاء الحصري عبر إدارة المنصة (الوضع الحالي):** يقوم مالك المنصة بإنشاء حساب صاحب الشبكة واختيار باقته واستلام الرسوم نقداً أو عبر بنكك/فودافون كاش قبل تسليمه الحساب.

### 3.2 ربط الباقات بالميزات المدفوعة
- **الوضع البرمجي الفعلي:**
  - جدول `subscription_plans` يحتوي على حقل JSON مرن باسم `features` يحدد:
    - `cardGenerationLimit` أو `cardLimit`: الحد الأقصى للكروت الشهرية.
    - `maxRouters`: عدد أجهزة الراوتر المسموح بربطها.
    - `isUnlimited`: علم الحصص المفتوحة.
- **تطبيق الحدود في الباك إند:**
  - **حدود الكروت:** مطبقة بصرامة عبر `QuotasService` مع قفل الصفوف `SELECT ... FOR UPDATE` لمنع التجاوز المتزامن وحساب الدورة الفاتورية الشهرية.
  - **حدود الأجهزة:** مطبقة بصرامة عبر `DevicesService.create` (الأسطر 115-122) برفض إضافة أي راوتر إضافي يكسر حاجز `maxRouters` برمز خطأ `ROUTER_LIMIT_EXCEEDED`.
  - **تصميم صفحات HotSpot:** *غير مقيد حالياً بباقة معينة*. القوالب والتصميم متاحة لجميع المستأجرين النشطين.
- **القرار المطلوب من صاحب المشروع:** هل ميزة تخصيص صفحات الهوتسبوت ميزة قياسية في كل الباقات، أم ميزة حصرية لباقات معينة (مثل باقة Pro وباقة Enterprise)؟

### 3.3 التحقق من تكامل وظائف HotSpot و PPPoE والكروت والطباعة
- **باقات وسرعات الهوتسبوت (`HotspotProfiles`):** تعمل عبر تكامل فعلي مع `/ip/hotspot/user/profile` لمزامنة السرعات (`rate-limit`) والصلاحية والمستخدمين المشتركين.
- **اشتراكات PPPoE للبرودباند:** تعمل عبر تكامل فعلي مع `/ppp/profile` و `/ppp/secret` وتدعم عزل المشتركين وفصل الجلسات اللحظي (`/ppp/active/remove`).
- **توليد الكروت ومخزنها:** يعمل عبر محرك تشفير آمن يولد أكواداً عشوائية فريدة غير قابلة للتخمين، ويحجز الحصص ذرياً في قاعدة البيانات.
- **استوديو وقوالب الطباعة (Print Studio):** نظام حقيقي 100% يولد مستندات PDF متوافقة مع الطباعة الحرارية 80mm و 58mm وشبكات ورق A4 (حتى 100 كرت بالصفحة) مع دعم كامل للغة العربية والـ RTL والباركود و QR Code.

## 4. مراجعة الأمان والتشغيل والاستقرار

### 4.1 عزل المستأجرين والتحكم بالصلاحيات (RBAC)
- جميع جداول البيانات الأساسية مفهرسة بـ `tenantId`.
- حراس النظام (`JwtAuthGuard`, `RolesGuard`, `TenantAccessGuard`) تمنع وصول أي مستخدم لبيانات خارج مستأجره.
- الأدوار محددة بدقة:
  - `SUPER_ADMIN`: إدارة المنصة، الباقات، مراقبة كافة الشبكات.
  - `TENANT_ADMIN`: إدارة شبكته، أجهزته، أسعار كروته، وموظفيه.
  - `CASHIER`: صلاحيات بيع الكروت وطباعة الإيصالات وإغلاق الورديات فقط (ممنوع من تعديل إعدادات الراوتر أو الباقات).

### 4.2 تشفير كلمات المرور ومفاتيح الحماية
- كلمات مرور المستخدمين مشفرة باستخدام خوارزمية **Argon2id** (أحدث وأقوى معايير التشفير عالمياً ضد هجمات القوة الغاشمة و GPU-cracking).
- بيانات اعتماد أجهزة الراوتر مشفرة في قاعدة البيانات بواسطة **AES-256-GCM** مع مفاتيح وتواقيع تحقق مصادق عليها.
- وكيل Windows LAN Agent يخزن توكن الاتصال وبيانات الراوتر محلياً في خزانة مشفرة عبر **Windows Data Protection API (DPAPI)** الخاصة بنظام التشغيل.

### 4.3 إدارة الأوامر، انقطاع الاتصال، وتفادي النجاح الوهمي (No False Positives)
- **دورة حياة الأمر:**
  $$\text{PENDING} \longrightarrow \text{DISPATCHED} \longrightarrow \text{COMPLETED} \quad \text{أو} \quad \text{FAILED / EXPIRED}$$
- **التأكيد الإلزامي:** لا يتم تحديث حالة أي أمر إلى `COMPLETED` في قاعدة البيانات إلا بعد أن يرسل الوكيل تقرير تنفيذ رسمي `outcome: 'COMPLETED'` مصحوباً بالنتيجة المستلمة من RouterOS.
- **معالجة الانقطاع والأخطاء:**
  - إذا انقطع الاتصال بين الوكيل والراوتر، يرسل الوكيل `outcome: 'FAILED'` مع تفاصيل الخطأ الدقيقة، ويظهر في واجهة المستخدم تنبيه أحمر بالخطأ.
  - إذا توقف الوكيل بالكامل، ينتهي وقت الأمر بعد انتهاء مهلة `expiresAt` ويتحول إلى `EXPIRED`، مما يمنع تعليق النظام أو إيهام المستخدم بنجاح العملية.

## 6. سجل المخاطر والمشكلات المصنفة حسب الخطورة (Severity Matrix)

### 🔴 مخاطر حرجة (Critical - يجب الانتباه لها أثناء الاختبار الميداني)
1. **طريقة رفع الملفات في RouterOS Flash Devices:**
   - *الوصف:* بعض موديلات ميكروتك (مثل RouterBOARD ذات ذاكرة 16MB Flash) ترفض الكتابة في المسار `hotspot/` وتلزم استخدام `flash/hotspot/`.
   - *الأثر:* قد يفشل أمر النشر بـ `cannot create file` إذا لم يتم إدخال مسار الفلاش المناسب للجهاز.
2. **حد محتوى الـ HTML عبر API ميكروتك:**
   - *الوصف:* قد يرفض الراوتر نصوصاً تتجاوز حداً معيناً في أمر واحد عند بطء معالج الراوتر.
   - *الإجراء:* قالب SudaFi الحالي خفيف جداً (~2.5KB)، ولكن يلزم اختباره على جهاز حقيقي ذي مواصفات متواضعة (مثل RB750r2 أو hEX lite).

### 🟡 مخاطر متوسطة (Medium - تتطلب تحسيناً قبل الإطلاق التجاري العام)
1. **غياب شاشة التسجيل الذاتي في الواجهات الأمامية:**
   - *الوصف:* العميل الجديد لا يستطيع فتح حساب بنفسه من شاشة الدخول، ويلزم تدخّل الإدارة أو إضافة الشاشة بعد اعتماد السياسة التجارية.
2. **عرض الصور الخارجية تحت الـ Walled Garden:**
   - *الوصف:* إذا كان للشبكة شعار برابط خارجي، فلن يظهر لعميل الواي فاي قبل تسجيل الدخول ما لم يُسمح بنطاق الصورة في الراوتر.
   - *الحل المقترح:* تحويل الشعارات الصغيرة المرفوعة إلى Data URI مدمجة داخل ملف الـ HTML مباشرة.

### 🟢 مخاطر منخفضة (Low - تحسينات تجربة المستخدم)
1. **أجهزة ذات إصدار RouterOS قديم جداً (أقل من v6.45):**
   - *الوصف:* الإصدارات الأقدم من 6.45 تستخدم نظام تشفير قديم في واجهة الـ API. المنظومة الحالية تدعم RouterOS v6.45+ و v7.x بالكامل.

عند توفر راوتر MikroTik تجريبي للبدء في الاختبار الميداني، يجب تنفيذ الخطوات التالية بالترتيب:

- [ ] تثبيت وتشغيل Windows LAN Agent على حاسوب متصل بنفس شبكة الراوتر المحلية.
- [ ] إدخال كود الاقتران السداسي المولد من لوحة التحكم والتأكد من تحول حالة الراوتر إلى `🟢 ONLINE`.
- [ ] سحب قراءات المراقبة الحية (CPU Load, Free RAM, Active Sessions) ومطابقتها مع WinBox.

### المرحلة 2: اختبار توليد ونشر كروت HotSpot
- [ ] إنشاء باقة هوتسبوت تجريبية (مثلاً 1 ساعة - سرعة 2M/2M) وتوليد دفعة من 10 كروت.
- [ ] التحقق من ظهور المستخدمين في WinBox تحت القائمة `/ip hotspot user`.
- [ ] تجربة اتصال هاتف ذكي بكود الكرت والتحقق من فتح الإنترنت وتطبيق السرعة وخصم الرصيد.

### المرحلة 3: اختبار نشر صفحة تسجيل الدخول (Captive Portal)
- [ ] الدخول إلى مصمم الصفحات من لوحة التحكم واختيار قالب (Starlink Cyan).
- [ ] تعديل اسم الشبكة والشعار وأرقام الدعم، ثم النقر على "نشر للراوتر".
- [ ] متابعة انتقال الأمر من `PENDING` إلى `DISPATCHED` ثم `COMPLETED`.
- [ ] فتح WinBox ومراجعة مجلد `/files` للتأكد من وجود `hotspot/login.html` و `hotspot/status.html`.
- [ ] اتصال هاتف بالشبكة والتأكد من انبثاق صفحة الدخول بالتصميم والألوان المحددة.

### المرحلة 4: اختبار اشتراكات PPPoE للبرودباند
- [ ] إضافة بروفايل PPPoE ومستخدم تجريبي عبر لوحة التحكم.
- [ ] التحقق من ظهور المستخدم في `/ppp secret`.
- [ ] محاكاة اتصال راوتر منزلي ومطابقة ظهور الجلسة في `/ppp active`.
- [ ] تجربة فصل المستخدم من لوحة التحكم والتأكد من انقطاع اتصاله في الراوتر فورياً.

### المرحلة 5: اختبار استوديو الطباعة والتطبيق غير المتصل
- [ ] تصدير كروت بصيغة PDF A4 وطباعتها حرارياً والتحقق من وضوح كود الكرت والباركود.
- [ ] تفعيل وضع عدم الاتصال في تطبيق الموبايل، بيع كرت من المحفظة، ثم تشغيل المزامنة عند عودة الإنترنت ومطابقة تحديث حالة الكرت إلى `USED`.

## 9. ما يجب تجهيزه قبل بدء الاختبار الميداني (Pre-Flight Checklist)

1. حاسوب بنظام Windows (Windows 10/11) لتشغيل الوكيل (`@mikrotik-saas/agent`).
2. جهاز راوتر ميكروتك تجريبي (مثل hEX أو hAP) محدث لإصدار RouterOS 6.48+ أو 7.x، مع تفعيل خدمة API (`/ip service enable api`).
3. التأكد من اسم المستخدم وكلمة المرور الخاصة بإدارة الراوتر بصلاحيات `write` أو `full`.
4. هاتف ذكي لاختبار الاتصال بشبكة الواي فاي وتجربة كروت الدخول.

---
**الخلاصة:**  
الكود في المنظومة متكامل ومستقر، تم التحقق من سلامة البناء واجتياز 100% من الاختبارات، والنظام جاهز تماماً للانتقال إلى مرحلة الفحص الميداني على راوتر تجارب حقيقي وفق الخطة أعلاه.
