## 1. الملفات التي تمت مراجعتها وتعديلها

### 1.1 الملفات المعدلة أثناء التدقيق:
1. **`apps/api/src/modules/devices/devices.service.ts`:**
   - **الخلل المكتشف:** كان فحص الاشتراكات في دالة إضافة الراوتر `create` يتحقق فقط من وجود اشتراك بحالة `ACTIVE` دون فحص تاريخ الانتهاء (`expiresAt <= now`). إذا انتهت فترة الاشتراك ولكن لم يتم تفعيل مهمة cron لقلب الحالة، كان بإمكان صاحب الشبكة تجاوز واجهة التطبيق وإضافة راوترات جديدة عبر الـ API.
   - **الإصلاح المنفذ:** إضافة فحص صارم ومباشر:
     ```typescript
     if (new Date(subscription.expiresAt).getTime() <= Date.now()) {
       throw new ForbiddenException({
         code: 'SUBSCRIPTION_EXPIRED',
         message: 'انتهت صلاحية اشتراك الشبكة. يرجى تجديد الباقة لإضافة أجهزة راوتر جديدة.',
       });
     }
     ```
2. **`apps/api/src/modules/devices/devices.service.spec.ts`:**
   - إضافة اختبار وحدة آلي يختبر رفض إضافة راوتر لاشتراك منتهي الصلاحية والتأكد من إرجاع `SUBSCRIPTION_EXPIRED`.
3. **`apps/api/src/modules/auth/auth.service.ts` & `auth.service.spec.ts`:**
   - مراجعة مسار التسجيل والتأكد من منع إنشاء أي اشتراك مدفوع تلقائياً.
4. **`apps/api/src/modules/tenants/tenants.controller.ts` & `tenants-rbac.spec.ts`:**
   - مراجعة وقصر نقطة النهاية `POST /tenants/current/wallet/recharge` على دور `SUPER_ADMIN` حصراً.
