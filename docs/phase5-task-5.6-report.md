## 3. نتائج اختبار سيناريوهات التسجيل والاشتراكات (بيانات اختبار معزولة)

تم اختبار السيناريوهات العشرة المطلوبة للتأكد من انضباط الدورة التجارية والأمنية:

1. **تسجيل صاحب شبكة جديد:**
   - تم التحقق من تسجيل منشأة جديدة ببيانات سليمة وتشفير كلمة المرور بـ `Argon2id` وربط عملة `SDG`.
   - **التحقق من عدم منح اشتراك مجاني مدفوع:** الحساب الجديد ينشأ بدون أي اشتراك، ولا يُمنح 30 يوماً مجانية.
2. **تسجيل الدخول بالحساب الجديد:**
   - الحساب يسجل دخوله بنجاح ويحصل على توكن JWT برتبة `TENANT_ADMIN`.
3. **استخدام الوظائف المجانية:**
   - تفتح لوحة التحكم بنجاح وتظهر تفاصيل المنشأة مع `plan: 'NONE', status: 'INACTIVE'`.
   - استوديو تصميم قوالب الكروت يعمل بنجاح مع معاينة القوالب.
   - مصمم صفحات HotSpot يعمل بالكامل في وضع المسودة والمعاينة المتجاوبة.
   - قراءة الرصيد تظهر `0.00 SDG`.
4. **محاولة استخدام الوظائف المدفوعة قبل التفعيل:**
   - استدعاء توليد الكروت `POST /cards/batches` يُرفض فورياً من الـ Backend برمز `403 Forbidden` (`SUBSCRIPTION_REQUIRED`).
   - استدعاء إضافة راوتر `POST /devices` يُرفض فورياً برمز `403 Forbidden` (`SUBSCRIPTION_REQUIRED`).
5. **تفعيل الاشتراك من حساب Super Admin:**
   - يتم استدعاء `POST /admin/tenants/:id/subscription/approve` بواسطة Super Admin لتحديد باقة الاختبار (مثل `PRO`) والدورة ومدة الصلاحية وملاحظات الإيصال اليدوي.
   - يتم تفعيل الاشتراك وتوثيق `approvedBy: superAdminId` في قاعدة البيانات وسجل التدقيق.
6. **إتاحة الوظائف بعد التفعيل:**
   - بعد تفعيل الاشتراك، يتمكن صاحب الشبكة من إضافة راوتر وتوليد الكروت ضمن سقف الباقة وحصتها الشهرية.
7. **اختبار انتهاء الاشتراك وإيقافه:**
   - عند انتهاء الصلاحية (`expiresAt <= now`) أو تعليق المنشأة (`SUSPENDED`)، يتم حظر توليد الكروت وإضافة الأجهزة برمز `SUBSCRIPTION_EXPIRED` أو `TENANT_SUSPENDED`.
8. **عزل بيانات المؤسسات (Multi-Tenancy):**
   - محاولة مستخدم من منشأة (A) قراءة أو تعديل كروت أو أجهزة أو اشتراكات منشأة (B) تفشل وتعود بقائمة فارغة أو خطأ وصول لأن الاستعلامات مفلترة بـ `where: { tenantId }` المستخرج من التوكن المشفر.
9. **منع التفعيل والشحن الذاتي:**
   - مسار تفعيل الاشتراكات ومسار شحن الرصيد المالي محميان بحارس الصلاحيات `RolesGuard` وقاصران على `SUPER_ADMIN`؛ أي محاولة استدعاء من صاحب شبكة أو كاشير ترفض فورياً برمز 403.
10. **عدم وجود خصم مالي تلقائي:**
    - المنظومة لا تحتوي على أي بوابات دفع آلية أو خصومات مفاجئة، والتفعيل يتم يدوياً بعد التحصيل الفعلي.

## 4. نتائج اختبار الوظائف الأساسية بالمحاكاة (Mock Validation)

تم فحص ومحاكاة المكونات التقنية بدون راوتر حقيقي:
- **إدارة الراوترات:** فحص حفظ بيانات الاتصال المشفرة بـ AES-256-GCM مع التحقق من تكرار المنافذ والـ IP.
- **كروت HotSpot:** خوارزمية CSPRNG تولد أكواداً عشوائية فريدة وتوزع الكروت على الدفعات مع فحص الحصص.
- **بروفايلات السرعات:** حفظ إعدادات الـ Rate Limit وتوافقها مع صيغ ميكروتك (مثل `2M/2M` أو `4M/8M`).
- **اشتراكات PPPoE:** حفظ كلمات المرور المشفرة وعزل الحسابات ومحاكاة الفصل الفوري للجلسات.
- **مصمم صفحات HotSpot:** فحص توليد كود HTML5 سليم ومتجاوب وخالٍ من ثغرات XSS أو مسارات غير مصرح بها.
- **استوديو الطباعة وإخراج PDF:** توليد ملفات PDF حقيقية جاهزة للطباعة الحرارية والشيتات A4 مع دعم اللغة العربية ورموز QR.
- **وكيل الشبكة المحاكى (`MockRouterWorker`):**
  - محاكاة استقبال وتنفيذ أوامر توليد الكروت ورفع ملفات الهوتسبوت وإدارة PPPoE.
  - محاكاة انقطاع الاتصال واستعادة الاتصال الذاتي (Reconnection & Heartbeat Resumption).
  - رفض الأوامر الخطرة غير المصرح بها (مثل أوامر التيرمينال المباشرة).

> **تنبيه هندسي:** نجاح اختبارات المحاكاة ونجاح المعاينة داخل المتصفح يثبتان سلامة المنطق البرمجي، لكنهما **لا يُعدان إثباتاً نهائياً** على استجابة جهاز MikroTik الفعلي في ظروف الشبكة الحقيقية.

## 5. خطة وتجهيز اختبار الراوتر الحقيقي (Field Test Execution Plan)

### 5.1 المتطلبات التقنية للاختبار الميداني
1. **إصدارات RouterOS المدعومة:**
   - RouterOS v6.45+ (RouterOS v6 Long-Term / Stable).
   - RouterOS v7.x (RouterOS v7.1 فأحدث).
2. **نوع الاتصال المعماري:**
   - اتصال آمن معكوس (Reverse HTTPS Polling): يقوم الوكيل المنصب على جهاز الحاسوب بالاتصال بالخادم السحابي عبر HTTPS، ثم يتصل محلياً بالراوتر عبر منفذ الـ API الداخلي (`8728` أو `8729 SSL`).
   - **لا يتطلب** راوتر ميكروتك وجود IP حقيقي عام أو فتح منافذ (Port Forwarding) على الإنترنت.
3. **التجهيزات المطلوبة في الموقع:**
   - حاسوب يعمل بنظام Windows (10 أو 11) لتشغيل الوكيل (`@mikrotik-saas/agent`).
   - جهاز راوتر MikroTik تجريبي (مثل hEX أو hAP ac2 أو RB750Gr3) موصول بنفس شبكة الحاسوب المحلية.
   - تفعيل خدمة الـ API على الراوتر: `/ip service enable api port=8728`.
   - حساب مدير على الراوتر بصلاحيات `full` أو `write`.
   - هاتف ذكي (Android أو iOS) لاختبار تطبيق Flutter والاتصال بنقطة الواي فاي.
   - طابعة إيصالات حرارية تجريبية (Bluetooth أو USB) أو طابعة A4 لتجربة طباعة الكروت.

### 5.2 مراحل الاختبار الميداني التسلسلية على الراوتر
```
الخطوة 1: ربط الراوتر والوكيل
```
