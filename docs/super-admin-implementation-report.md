## 1. الملخص التنفيذي
تم إنجاز المرحلة الثانية بالكامل وبنجاح فائق، محققين الأهداف التالية:
1. **لوحة تحكم مركزية للـ Super Admin:** تعرض مؤشرات أداء حقيقية للمنصة التجارية مستخرجة بالكامل من قاعدة البيانات مباشرة (بدون أي بيانات وهمية Mock)، تتضمن إحصاءات المستأجرين، الاشتراكات النشطة والمنتهية، حجم الكروت المستهلكة شهرياً، حالة الموجهات MikroTik المربوطة، وتوزيع العملاء حسب الباقات.
2. **إدارة متقدمة لشبكات العملاء (Tenants):** جدول متكامل يدعم البحث الحي والتصفية بحسب الحالة (ACTIVE, SUSPENDED, EXPIRED) والترقيم الصفحي، مع إمكانية استعراض تفاصيل العميل، موجهاته ومستخدميه، تفعيل وتعليق الحسابات، وتعيين الاشتراكات اليدوية، وسجل التدقيق الخاص بالشبكة.
3. **نظام إدارة الخطط التجارية (Subscription Plans):** وحدة Backend كاملة (`PlansModule`) ووواجهة إدارة في React تتيح إنشاء، تعديل، وتبديل تفعيل الباقات التجارية، مع التحديد الصريح لحدود الموجهات والكروت الشهرية، والتفريق الحاسم بين الباقة غير المحدودة (`isUnlimited: true`) والحدود الرقمية، والمنع التام للقيم السالبة أو الالتباس.
4. **إدارة دورة حياة الاشتراكات (Subscriptions Lifecycle):** تفعيل يدوي للاشتراكات، إلغاء الاشتراكات المتعارضة تلقائياً لضمان بقاء اشتراك نشط واحد فقط للمستأجر، وتجديد وتمديد الاشتراكات بعدد محدد من الأشهر مع تسجيل الملاحظات وسجلات التدقيق.
5. **فرض الأمان والصلاحيات الصارمة (RBAC):** حماية كافة المسارات الحساسة على مستوى الـ Backend باستخدام حراس المصادقة والأدوار `@Roles(RoleName.SUPER_ADMIN)` و`RolesGuard` و`TenantGuard`، مع عدم كشف كلمات مرور الموجهات أو أسرار التشفير.
6. **التوافق التام والاستقرار:** نجاح جميع اختبارات الـ API (97 اختباراً عبر 17 جناح اختبار)، ونجاح بناء تطبيق الويب React Admin، ونجاح اختبارات تطبيق Flutter للأجهزة المحمولة بنسبة 100%.

## 3. واجهات الـ Backend البرمجية (APIs) المضافة والمحدثة

تمت إضافة وحدة كاملة `PlansModule` وتوسيع `TenantsController` و`TenantsService` بحماية صارمة تمنع وصول أي مستخدم باستثناء `SUPER_ADMIN`:

### 3.1. واجهات الخطط التجارية (`/api/v1/plans`)
- `GET /api/v1/plans`: جلب جميع الخطط المتاحة (مع معامل اختياري `includeInactive=true`).
- `GET /api/v1/plans/:id`: جلب تفاصيل خطة محددة مع إحصاءات المشتركين.
- `POST /api/v1/plans`: إنشاء خطة جديدة مع التحقق الصارم من المدخلات عبر `CreatePlanDto`، وتسجيل حدث التدقيق `plan:created`.
- `PATCH /api/v1/plans/:id`: تعديل أسعار وحدود وميزات الخطة عبر `UpdatePlanDto`، وتسجيل حدث التدقيق `plan:updated`.
- `PATCH /api/v1/plans/:id/toggle-active`: تفعيل أو تعطيل الباقة للاشتراكات الجديدة، وتسجيل حدث `plan:status_toggled`.

### 3.2. واجهات لوحة المنصة والشبكات والاشتراكات (`/api/v1/tenants`)
- `GET /api/v1/tenants/admin/overview`: توفير كافة المؤشرات الرقمية الحقيقية للمنصة (الشبكات، الاشتراكات، استهلاك الكروت الشهري، الموجهات، توزيع الباقات، أحدث المسجلين).
- `GET /api/v1/tenants`: جلب قائمة المستأجرين مع دعم المعاملات `search` و`status` و`page` و`limit` مع استجابة مرقمة متوافقة بالكامل مع الاستدعاءات القديمة.
- `GET /api/v1/tenants/:id`: جلب كامل تفاصيل المستأجر (الموجهات، المستخدمين، الاشتراكات).
- `PATCH /api/v1/tenants/:id/status`: تعديل حالة المستأجر (`ACTIVE` أو `SUSPENDED`) مع حفظ السبب وتسجيل حدث تدقيق.
- `GET /api/v1/tenants/:id/audit-logs`: جلب سجل العمليات والتدقيق الخاص بمستأجر محدد مع ترقيم الصفحات.
- `GET /api/v1/tenants/admin/subscriptions`: استعراض الاشتراكات مع التصفية بالشبكة أو الحالة أو الباقة والترقيم الصفحي.
- `POST /api/v1/tenants/:id/subscription/approve`: اعتماد أو تفعيل اشتراك يدوي للشبكة، مع **إلغاء الاشتراكات النشطة السابقة آلياً لمنع التضارب**.
- `POST /api/v1/tenants/subscriptions/:id/renew`: تمديد صلاحية اشتراك قائم بعدد محدد من الأشهر وتحديث حالته لـ `ACTIVE`.
- `PATCH /api/v1/tenants/subscriptions/:id/status`: تعديل حالة الاشتراك (`ACTIVE`, `CANCELLED`, `EXPIRED`) وتسجيل سجل التدقيق.

## 4. نموذج البيانات وتغييرات قاعدة البيانات
- **استخدام النماذج الحالية بدون تعديلات تدميرية:** تم الحفاظ على هيكل جداول PostgreSQL الحالي في Supabase دون الحاجة لأي migrations خطرة أو تدميرية:
  - جدول `subscription_plans`: الحقول `id`, `name`, `nameAr`, `description`, `maxRouters`, `priceMonthly`, `priceYearly`, `features` (Json)، `isActive`.
  - جدول `subscriptions`: الحقول `id`, `tenantId`, `planId`, `status`, `billingCycle`, `startsAt`, `expiresAt`, `maxRouters`, `price`, `approvedBy`, `notes`.
  - جدول `audit_logs`: تسخيره بالكامل لتوثيق جميع العمليات الإدارية الحساسة (`action`, `entity`, `entityId`, `oldValues`, `newValues`, `userId`, `tenantId`).
- **معنى حصة الكروت:** تم الالتزام التام بالقواعد المثبتة:
  - `features.isUnlimited = true` أو `cardGenerationLimit = null`: يعني باقة غير محدودة الكروت.
  - `cardGenerationLimit = 0`: يعني منع توليد الكروت لهذه الباقة تماماً.
  - قيمة موجبة: تمثل الحد الأقصى الشهري بدقة.

## 5. الصلاحيات والأمان وعزل المستأجرين
1. **الفرض على مستوى الـ Backend:** حماية جميع نقاط النهاية الإدارية باستخدام الحراس:
   ```typescript
   @UseGuards(JwtAuthGuard, RolesGuard)
   @Roles(RoleName.SUPER_ADMIN)
   ```
   بحيث يرفض الـ Backend أي طلب قادم من مستخدم عادي برمز `403 Forbidden` بغض النظر عن الواجهة الأمامية.
2. **عزل بيانات المستأجرين:** الحفاظ على `TenantGuard` بحيث يمنع أي مستأجر من استدعاء أو استعراض بيانات مستأجر آخر.
3. **حماية الأسرار وكلمات المرور:** استبعاد حقول كلمات مرور الموجهات (`passwordEncrypted`, `authTag`, `iv`) وكلمات مرور المستخدمين من كافة استجابات واجهات المستأجرين والتفاصيل الإدارية.
4. **سجل تدقيق شامل (Audit Trail):** كل عملية إنشاء أو تعديل خطة، أو تعليق شبكة، أو تفعيل أو تجديد اشتراك يتم توثيقها في جدول `audit_logs` متضمنة معرف منفذ العملية والقيم السابقة والجديدة.
