## 2. مراجعة التناقضات والفروقات المكتشفة في التدقيق (Discrepancy Audit)

1. **أسماء الباقات في الشرح مقابل الكود الفعلي:**
   - **في الكود الفعلي وقاعدة البيانات:** أسماء الباقات المعرفة في جدول `subscription_plans` هي: `BASIC` (الباقة الأساسية)، `PRO` (الباقة المتقدمة)، و `BUSINESS` (باقة الأعمال).
   - **المطابقة:** متطابقة وموحدة بين الـ Backend ولوحة تحكم Super Admin، ويوصى باستخدام هذه الأسماء رسمياً في التسويق للعملاء.
2. **نموذج الدفع المالي والشحن:**
   - **الواقع الفعلي المنفذ:** تم اعتماد نموذج التحصيل المالي المباشر يدويًا (كاش أو تحويل بنكك)، ثم يقوم **Super Admin** بتفعيل أو تجديد الاشتراك مع تسجيل رقم الإيصال.
   - **تأمين المحفظة:** تم قصر مسار `POST /tenants/current/wallet/recharge` على `SUPER_ADMIN` حصراً لمنع أي شحن ذاتي غير مصرح به، مع الحفاظ على سجل المعاملات المالية السابقة سليمًا.
3. **طبيعة تشغيل وكيل الشبكة (Windows LAN Agent):**
   - **الواقع الفعلي:** الوكيل حالياً هو تطبيق Node.js CLI يعمل عبر الأمر `node dist/main.js run`، وإذا أُغلق الـ Terminal يتوقف الوكيل.
   - **الحل المطلوب قبل الإنتاج:** تسجيله كمهمة إقلاع تلقائي عبر Windows Task Scheduler أو تغليفه باستخدام أداة مثل NSSM ليعمل كـ Windows Service صامتة في الخلفية عند بدء تشغيل الجهاز.
4. **الطباعة المادية في تطبيق الموبايل:**
   - **الواقع الفعلي:** التطبيق يولد ملفات PDF عربية احترافية، ويدعم إرسال أوامر خام ESC/POS عبر مقبس الشبكة (Port 9100).
   - **الملاحظة:** طباعة البلوتوث المباشرة على طابعات الجيب تتطلب تعريف الطابعة في إعدادات الهاتف واستخدام نافذة الطباعة الافتراضية للنظام (`Printing.layoutPdf`)، وهو ما يعمل بسلاسة دون الحاجة لتعريفات معقدة.
5. **فحص سريان الاشتراك في كافة العمليات:**
   - **الواقع الفعلي:** يتم فحص سريان الاشتراك وتاريخ انتهائه (`expiresAt <= now`) بدقة متناهية في:
     - توليد دفعات الكروت (`CardsService.generateBatch`).
     - إضافة موجهات راوتر جديدة (`DevicesService.create`).
   - **التحسين الموصى به:** ربط عمليات إضافة حسابات PPPoE الجديدة أو نشر قوالب الهوتسبوت أيضاً بفحص الاشتراك النشط نفسه.

## 3. قائمة الاختبارات التي تتطلب عتاداً فيزيائياً حقيقياً (Physical Lab Tests)

هذه الوظائف اجتازت كافة الاختبارات البرمجية والمحاكاة، ولكن لا يمكن الجزم بعملها ميدانياً 100% دون التجربة على عتاد فيزيائي:

1. **جهاز MikroTik RouterOS v6 و v7 فيزيائي:**
   - التأكد من رفع ملفات الهوتسبوت إلى مجلد `/file` والتعامل مع مسار `flash/hotspot` في أجهزة RouterBOARD التي تعتمد ذاكرة Flash صغيرة.
   - التأكد من قراءة أوامر API Socket في بيئات الشبكات الضعيفة.
   - فحص استجابة أمر قطع جلسة PPPoE الحية (`/ppp active remove`).
2. **هاتف ذكي حقيقي (Android / iOS):**
   - اختبار تجربة انبثاق صفحة الدخول (Captive Portal Browser Popup) عند الاتصال بشبكة الواي فاي.
   - اختبار قراءة رمز QR بكاميرا الهاتف للاتصال المباشر.
3. **طابعة إيصالات حرارية حقيقية:**
   - اختبار وضوح طباعة النصوص العربية والباركود على ورق بعرض 58mm و 80mm ومطابقة سرعة القاطع التلقائي.

### القرار: **النظام مؤهل وجاهز بنسبة 100% لبدء مرحلة الاختبار الميداني المقيد (Lab / Controlled Field Test)**.
