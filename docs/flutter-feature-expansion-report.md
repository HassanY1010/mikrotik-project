## 1. ملخص الميزات الأربع المنفذة

تمت إضافة الميزات الأربع المطلوبة بالكامل في تطبيق Flutter للموبايل (`apps/mobile`) وإدماجها بصورة عميقة مع خادم NestJS API، قاعدة بيانات PostgreSQL/Prisma، لوحة تحكم React، وأجهزة وتوجيهات MikroTik RouterOS دون الاعتماد على أي بيانات وهمية أو واجهات شكلية:

1. **الميزة الأولى: تعديل وتصميم قوالب الطباعة واستيرادها من الجهاز**
   - استوديو ومحرر متكامل لقوالب طباعة كروت الهوتسبوت داخل الهاتف.
   - إمكانية تعديل الأبعاد (العرض والارتفاع بالميليمتر)، الاتجاه (أفقي/عمودي)، الألوان الأساسية ولون التمييز (Hex Picker)، إظهار/إخفاء العناصر (الباركود QR، رمز PIN، السعر، مدة الصلاحية، السرعة، الشعار)، النصوص الإرشادية، وتخصيص هوامش وحدود الكرت.
   - زر «استيراد قالب من الجهاز» مع فحص أمان صارم: التحقق من صيغة JSON، التحقق من الحقول الإلزامية، تحديد حد أقصى لحجم الملف (500KB) لمنع تسريب الذاكرة، مع المعاينة الفورية قبل الحفظ.
   - حفظ القوالب ومزامنتها مركزيًا عبر الـ REST API (`/api/v1/card-templates`) لتظهر فورًا في لوحة تحكم الويب، واستخدام القالب المخصص في توليد الدفعات وطباعة ملفات A4 ومشاركتها عبر PDF.

2. **الميزة الثانية: إنشاء وإدارة بروفايلات الوقت والسرعة من داخل Flutter**
   - واجهة مخصصة لإدارة وإنشاء وتعديل وحذف باقات وسرعات الهوتسبوت (`Hotspot Profiles`).
   - دعم كامل لحقول RouterOS: اسم البروفايل، الاسم التجاري للمشتركين (`displayName`)، قيود السرعة (`rateLimit` مثل `2M/2M`، `5M/5M`)، مدة الجلسة والصلاحية (`sessionTimeout`/`validity` مثل `1h`، `1d`)، السعر الافتراضي، عدد المستخدمين المتزامنين، والراوتر المستهدف.
   - تكامل حقيقي مع ميكروتك: إرسال الطلب عبر `POST /api/v1/hotspot/profiles` مع تنفيذ مزامنة فورية أو مؤجلة على الراوتر النشط عبر طبقة `MikrotikHotspotService` في الخادم.
   - زر لمزامنة الباقات مباشرة مع الراوتر وسحب أي بروفايلات موجودة مسبقًا في ميكروتك لحفظها محليًا وسحابيًا.

3. **الميزة الثالثة: قسم حساب المستخدم وإعدادات الأمان (حسابي)**
   - شاشة «حسابي وإعدادات الأمان» تسترجع البيانات الفعلية لجلسة المستخدم من الخادم عبر `GET /api/v1/auth/me`.
   - عرض الاسم الكامل، البريد الإلكتروني، رقم الهاتف، الدور والصلاحية (`SUPER_ADMIN`, `TENANT_ADMIN`, `MANAGER`, `CASHIER`)، اسم المؤسسة/الشبكة (`tenantName`)، حالة الحساب، والعملة المعتمدة.
   - إمكانية تغيير كلمة المرور بأمان تام عبر `POST /api/v1/auth/change-password` مع التحقق من كلمة المرور الحالية ومطابقة كلمة المرور الجديدة.
   - تسجيل الخروج الآمن ومسح الجلسة المخزنة في `flutter_secure_storage` بأمان مع حماية بيانات الأوفلاين.

4. **الميزة الرابعة: إنشاء وإدارة مستخدمي المنظومة من داخل التطبيق**
   - حصر وتخصيص زر ونموذج «إنشاء مستخدم جديد» فقط للأدوار المصرح لها (`TENANT_ADMIN` و `SUPER_ADMIN`).
   - نموذج إدخال آمن يتضمن: الاسم الكامل، البريد الإلكتروني، رقم الهاتف، اختيار الدور المسموح به (`CASHIER` أو `MANAGER`)، وكلمة المرور المشفرة.
   - إرسال الطلب عبر `POST /api/v1/users` مع عزل المستأجر الصارم في الخادم (حيث يستخرج الخادم `tenantId` تلقائيًا من الـ JWT Claims للجلسة النشطة دون السماح بالتلاعب بها من العميل).
   - شاشة مخصصة لإدارة مستخدمي المنظومة والموظفين، عرض بطاقات المستخدمين، أدوارهم، وحذف المستخدمين أو إلغاء تنشيطهم وفق الصلاحيات.

## 4. واجهات API المستخدمة والمدمجة

| الميزة | مسار الـ Endpoint | الطريقة | الوصف والتحقق |
| :--- | :--- | :--- | :--- |
| **قوالب الطباعة** | `/api/v1/card-templates` | `GET` | استرجاع كافة القوالب الخاصة بالمستأجر والقوالب الافتراضية للنظام. |
| **قوالب الطباعة** | `/api/v1/card-templates` | `POST` | إنشاء قالب جديد وحفظ تخطيط الألوان والعناصر في قاعدة البيانات. |
| **قوالب الطباعة** | `/api/v1/card-templates/:id` | `PATCH` | تحديث اسم القالب، ألوانه، أبعاده، أو تعيينه كافتراضي. |
| **قوالب الطباعة** | `/api/v1/card-templates/:id` | `DELETE` | حذف القالب وفق صلاحيات المستأجر. |
| **باقات الهوتسبوت** | `/api/v1/hotspot/profiles` | `GET` | جلب الباقات المخزنة للمستأجر مع تفاصيل الأسعار والسرعات. |
| **باقات الهوتسبوت** | `/api/v1/hotspot/profiles` | `POST` | إنشاء بروفايل في قاعدة البيانات وإرسال أوامر RouterOS للراوتر المتصل. |
| **باقات الهوتسبوت** | `/api/v1/hotspot/profiles/:id` | `PATCH` | تعديل بيانات البروفايل ومزامنة التغيير على الراوتر. |
| **باقات الهوتسبوت** | `/api/v1/hotspot/profiles/:id` | `DELETE` | حذف البروفايل بأمان مع التحقق من عدم وجود كروت نشطة مرتبطة به. |
| **باقات الهوتسبوت** | `/api/v1/hotspot/sync` | `POST` | مزامنة الباقات وسحب البروفايلات الحالية من جهاز MikroTik. |
| **حساب المستخدم** | `/api/v1/auth/me` | `GET` | جلب بيانات جلسة المستخدم المنبثقة من الـ JWT (الاسم، البريد، الدور، المستأجر). |
| **حساب المستخدم** | `/api/v1/auth/change-password` | `POST` | تغيير كلمة المرور بعد التحقق من كلمة المرور السابقة وتشفيرها عبر bcrypt. |
| **إنشاء المستخدمين** | `/api/v1/users` | `GET` | جلب قائمة مستخدمي المنظومة الخاصة بالمستأجر فقط. |
| **إنشاء المستخدمين** | `/api/v1/users` | `POST` | إنشاء حساب مستخدم جديد مقيد بـ `tenantId` المستخرج من جلسة المدير. |
| **إنشاء المستخدمين** | `/api/v1/users/:id` | `DELETE` | حذف مستخدم من المنظومة (غير مسموح بحذف النفس أو تجاوز الصلاحيات). |

## 8. اختبار التكامل مع MikroTik RouterOS

- يمر مسار إنشاء البروفايل عبر السلسلة المعمارية الآمنة:
  $$\text{Flutter Mobile} \xrightarrow{\text{Bearer JWT}} \text{NestJS API} \xrightarrow{\text{HotspotService}} \text{MikroTik RouterOS API/SSH}$$
- عند إنشاء بروفايل في Flutter:
  1. يتحقق الخادم من هوية المستأجر وصلاحياته.
  2. يتم فحص وجود الراوتر المستهدف في حالة اتصال (`Online`).
  3. يتم التحقق من عدم تكرار الاسم في جدول `HotspotProfile`.
  4. يُرسل أمر `/ip/hotspot/user/profile/add` إلى الراوتر مع ضبط `rate-limit` و `session-timeout`.
  5. إذا كان الراوتر غير متصل لحظياً، يُحفظ البروفايل كمسودة سحابية في قاعدة البيانات وتُعاد حالة `isSyncedToRouter: false` للتطبيق ليعلم المستخدم بحالة المزامنة دون خداعه.
  6. يتيح التطبيق إعادة المزامنة في أي وقت بضغطة زر.

## 9. معالجة حالات الفشل والاستقرار

- **انقطاع الاتصال:** لا يتوقف التطبيق أو ينهار؛ يتم التقاط أخطاء `DioException` وعرض رسائل تنبيهية واضحة باللغة العربية دون كشف أسرار فنية أو Stack Traces.
- **ملفات القوالب التالفة:** في شاشة استيراد القوالب، يتم فحص حجم الملف (<500KB)، ويتم التحقق من صيغة JSON والحقول الإلزامية عبر `try/catch` قبل فتح القالب في المحرر.
- **منع تكرار الإرسال:** تم تعطيل أزرار الحفظ والإنشاء أثناء وجود طلب معلق عبر مؤشرات التحميل `_isSubmitting` و `_isGenerating`.
- **انتهاء الجلسة:** عند استلام رمز `401 Unauthorized`، يقوم معترض `AuthInterceptor` إما بتجديد الرمز تلقائيًا عبر Refresh Token أو توجيه المستخدم لشاشة تسجيل الدخول بأمان.

## 10. الخطوات التي تتطلب تجربة يدوية أو بيئة مادية

1. **الطباعة على طابعة حرارية حقيقية:** تم اختبار توليد ملفات PDF ومشاركتها عبر بروتوكول الطباعة المدمج في نظام التشغيل (`printing` package)؛ التحقق النهائي على طابعة بلوتوث حرارية أو USB يتطلب توصيل طابعة فيزيائية بجهاز الاختبار.
2. **الربط مع راوتر MikroTik حقيقي قيد التشغيل:** تم التحقق من سلامة الأوامر وPayload الخاصة بـ RouterOS v6 و v7 في طبقة الـ API؛ المزامنة الحية تتطلب تشغيل الراوتر الفعلي وإدخال بيانات اعتماده في بيئة المستأجر.
3. **تثبيت ملف الـ APK:** تم التأكد من خلو المشروع تماماً من أي أخطاء تمنع البناء (`No issues found`); توليد APK وتثبيته على الهاتف الفعلي يتم عبر تشغيل `flutter build apk` متى ما رغب المستخدم في تجربة الحزمة على هاتفه الشخصي.
